# Финишер — панель дня

Однопользовательская веб-панель ежедневника: цель-результат, задачи дня, тайм-бокс,
разгрузка и трекер привычек на одном экране. Электронная версия бумажного планера
в духе The Finisher's Journal.

Весь фронтенд — один HTML-файл без зависимостей и сборки, вшитый в бинарник.
Сервер на Rust + axum хранит состояние в одном YAML-файле: ни базы, ни аккаунтов,
ни внешних сервисов.

## Запуск

```bash
cargo run
```

Открыть http://127.0.0.1:8080 — панель сохраняется автоматически через 400 мс после правки.

## Настройка

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `FINISHER_ADDR` | `127.0.0.1:8080` | адрес и порт |
| `FINISHER_DATA` | `<каталог сборки>/data/finisher-data.yaml` | путь к файлу состояния |

`FINISHER_DATA` стоит задавать всегда, кроме локальной разработки: путь по умолчанию
подставляется на этапе компиляции, поэтому бинарник без него пишет в каталог, где шла сборка.

## API

| Метод | Путь | Поведение |
|---|---|---|
| `GET` | `/` | панель |
| `GET` | `/api/state` | YAML-файл целиком; `204`, если данных ещё нет |
| `PUT` | `/api/state` | проверяет, что тело — валидный YAML, и атомарно пишет его (tmp + rename) |

## Формат данных

Файл состояния пишет фронтенд: ключ, а после двоеточия — значение в виде JSON.
Это валидный YAML, но читатель на стороне браузера понимает только эту форму, поэтому
править файл руками нужно в том же стиле — некавыченные значения, комментарии в конце
строки и блочные скаляры он не примет. Если разбор упал, панель показывает
«Файл данных не разобран» и выключает автосохранение, чтобы не затереть файл.

## Развёртывание

Бинарник под systemd на локальном порту, nginx проксирует подпуть (`location /finisher/`).
Фронтенд обращается к `api/state` относительным путём, поэтому работает за прокси на подпути
без правок.

Пошаговые команды установки, обновления и отката — в [DEPLOY.md](DEPLOY.md).
